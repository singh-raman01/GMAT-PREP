# The server owns the Session clock

A browser tab can be closed, throttled in the background or have its clock changed, and a timed Section must still end on time. The server counts each Section's elapsed time in short ticks of its own clock and saves it every few seconds; browsers only display it. It reads wall time rather than a monotonic clock, since a monotonic clock may stop while the machine sleeps and so hide the gap; a change to the system clock reads as a gap too, and is not counted. Closing the tab does not stop the clock, as on the exam. A gap between ticks longer than a few seconds means the process stopped or the machine slept: that time is not counted, and the Session is marked interrupted. Every answer carries a sequence number, so a double click or a retried request is recorded once, and one device holds a Session at a time. Expected result: no client can change a Section's clock, and an Interruption shifts a Section's time by at most a few seconds.
